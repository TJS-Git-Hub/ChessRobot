# 第四代实时视觉观察

此入口持续采集真实相机、判断稳态，原图只标小号坐标，中文棋名放在右侧棋盘图。
它不会导入整机主程序、CH347、舵机或机械臂控制器，不会提交游戏走法。
相机安装、遮挡漏检、识别准确率及毫米精度仍须实物验证；这不是整机联调验收。

## 启动

在项目根目录运行。依赖见 requirements-vision-live.txt。
RTMPose、Nano 和辅助 MobileNet ONNX 仍从 recognition/models/onnx 读取。
只有一个默认识别方案，不提供模型切换或对比画面。

手部模型必须显式提供；缺失、相机断开或模型异常会拒绝输出，不回退样本图。
MediaPipe 官方模型说明：
https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker

首次准备手部遮挡模型（下载在项目外）：

    $visionTaskCache = Join-Path $env:USERPROFILE '.codex\cache\tasks\chessrobot-live'
    New-Item -ItemType Directory -Force -Path $visionTaskCache | Out-Null
    Invoke-WebRequest 'https://storage.googleapis.com/mediapipe-models/hand_landmarker/hand_landmarker/float16/latest/hand_landmarker.task' -OutFile (Join-Path $visionTaskCache 'hand_landmarker.task')
    python -B tools/vision_live.py --camera 2 --width 1920 --height 1080 --hand-model (Join-Path $visionTaskCache 'hand_landmarker.task') --output-dir (Join-Path $visionTaskCache 'session')

--camera 按本机编号选择；本次 AX USB2.0 为2，不保证其他电脑编号相同。
窗口会显示实际采集分辨率及实际采集帧率。请求值不等于设备支持值。
本机探测请求4K及若干更大尺寸均实际返回1920×1080；不是4K实测。
AX/DirectShow必须在分辨率、FPS设定后最后指定MJPEG；反过来会退回YUY2，
1080p实测约5fps。修正协商顺序后，同分辨率相机独立采集实测约29.3fps。
界面分别显示实际采集fps与实际预览fps，模型推理速度另计。
预览按屏幕缩放，推理仍取原始采集帧，窗口放大不增加原图细节。

## 操作与有效性

- 完整拍入四边及全部棋子，建议棋盘占据画面主要区域，留少量边缘。
- 不点击四角，不按空格；稳定后自动识别，两次不同新帧确认。
- 先配准画面以容忍小幅手抖，并归一化小幅整体亮度变化；中文标注随跟踪变换更新。
- 已确认棋盘后，运动检测只比较棋盘及外侧棋子的可见范围；画面旁边的背景运动不单独暂停。
- 对可辨认的局部变暗/柔和阴影估计平滑的中性光照场；不把这种亮度变化当成棋子移动。
- 手部检测保留归一化轮廓位置，只有与棋盘区域相交才暂停；尚无可靠棋盘几何时仍保守暂停。
- 明显移动、曝光突变、手部、角点不完整时撤下结果并重新确认。
- 尚未建立可信盘面时，个别识别不确定显示问号，不把整盘误判成正在运动。
- 建立可信盘面后，对实际新相机帧持续进行外观复核，通过时保持绿色可信状态。
- “画面稳定”和“全盘识别已确认”分开显示；不确定结果不提交为可信盘面。
- 相过河、将出九宫等摆放只作布局提醒，不改写实际棋子，也不阻止视觉稳定。
- 一帧返回的模型置信度不是保证；检测器也可能漏掉手，必须测试静止手及局部遮挡。
- R：重建观察基准。Q/Esc：退出并释放摄像头。S：保存原图、预览图和JSON。
- L：隐藏或显示原图小坐标。F：全屏。坐标只在棋子外有空位时显示。
- 每个原图坐标通过带白色描边的青色引线连接到对应棋子的外圈，不覆盖真实棋字。
  标签和引线避开其他棋子的字面；没有清晰位置时省略，不凭远近暗示对应关系。
- O：开关毫米偏置诊断请求。启用后对通过外观/分类检查的新帧重新测圆心，
  不复用上次神经推理缓存的圆心；蓝色十字为理论点，黄色圆心及箭头表示测量。
  诊断数字未经当前相机标定，不等于毫米精度通过，观察入口不提供可执行控制偏置。
- 移动/吃子仅显示观察候选，不作象棋规则或软件棋局提交；禁止据此接自动动作。

日志 events.jsonl、当前状态 status.json、预览 monitor_latest.jpg 保存在 --output-dir。
monitor_raw_latest.jpg是滚动更新的原始相机画面，供持续人工/代理核对，不保存整段视频。
按S才另存带时间戳的原图。无模型文件自动下载或隐式假图。
Windows读者短暂锁住监控文件时跳过该次发布并记录snapshot_busy_count，下一次重试；
可选截图更新失败不会因此关闭实时摄像头窗口。

## 改进内容及边界

### 已确认盘面的新帧外观复核

先由Nano/辅助分类与至少两张不同相机帧确认全部90格；建立参考时还要求
当前帧的分类结果与确认盘面完全一致且通过质量检查。参考原图与校正图自动保存为
reference_<epoch>_<frame>_raw.png和对应canonical.png，便于逐子复核。

之后约每0.15秒检查一张真正的新相机帧：验证完整几何、90个局部区域的结构及墨色色度，
容忍小幅白平衡、明暗和配准残差。外观参考图和分类身份在该观察代际内保持不变；
字形等高纹理区域使用严格相关检查；空白/细线等低纹理区域改用有界残差，
另加局部变化残差限制，防止低纹理相关系数不稳定而频繁误拒绝。
比较范围只覆盖最外交叉点外扩半格的有效区域，不将透视图外侧的桌面/阴影当作棋子变化。
残差使用带下限的局部对比度归一化，避免空白纸面很小的方差放大插值噪声；
仍保留局部字形、颜色和新增/消失棋子的拒绝检查。
当直接比较不通过时，额外拟合参考与当前图之间的低频乘性光照场，
宽中值窗口大于棋子直径，B/G/R使用相同且有界的增益，不替换字迹颜色。
补偿之后仍须通过相同的几何、字形、局部残差及墨色检查；
饱和反光、过暗、字迹被遮住或配准证据不足时仍拒绝，不通过保留旧结果强制绿色。
运动检测也使用此光照归一化，并检查局部色度变化，以免将有颜色的遮挡物当作阴影。
无明显变化时走轻量比较路径，避免每个预览帧都计算阴影场。
每张待复核画面直接与不变参考图作双向光流及RANSAC单应配准，
要求至少16个可靠特征、足够内点比例及全盘空间覆盖，不再累乘逐帧配准误差。
配准证据不足就暂停；成功后仅更新相机坐标传递，供显示与下一次分类裁图使用。
不从未确认的画面学习棋子身份，也不在变化盘面上逐渐适应模板。

每秒仍运行原始模型作独立诊断。短暂低置信或数量冲突不会单独推翻已由当前像素验证的盘面；
周期分类沿用刚通过外观复核的几何裁图，避免重新预测角点的小幅跳动改变分类输入；
角点模型仍独立检测，低置信、不完整或与跟踪几何严重不一致都会拒绝。
当前像素仍匹配参考时，单次弱模型猜测不推翻参考；替代盘面须在两个不同新帧中连续一致，
且变化格置信度至少0.80，才触发保守重确认。没有0.35秒内的新鲜参考支持则不延迟冲突处理。
原始遮挡x、几何失败、上述连续强模型冲突、局部外观变化、手部、移动和断流均重新确认。
模型处理超过5秒也会暂停确认。改变布局后必须重新经过模型与多帧确认才能建立新参考。

绿色时JSON可能为source=appearance_verified：captured_at/frame_id对应本次实际新帧，
classification_reference_time和classification_reference_frame_id单独标注初始分类参考；
conf_grid保持参考分类置信度，
confidence_source=reference_classification，不虚增模型概率。verification给出当前像素匹配质量，
verification_ms是外观复核耗时，不冒充神经网络推理耗时。
这类输出没有piece_offsets，offsets_valid=false；不得把它当作新的毫米测量。
每个跟踪输出最长有效0.35秒，必须不断取得通过复核的新帧；重复帧不增加验证计数。
实时入口限制OpenCV为最多4个线程，与ONNX/MediaPipe共享CPU资源；
手部结果过期的0.5秒保护阈值不放宽。status.json记录手部结果年龄及延迟P95。
手部检测有独立的持续取帧线程，不等待预览循环安排下一次任务；
预览繁忙时仍检查最新帧，旧中间帧不排队，检测异常不保留上次阴性结果。
当前像素先复核，再仲裁异步返回的模型意见，避免回调顺序造成虚假的证据过期。
外观或模型冲突的原始输入另存为appearance_rejected_*及neural_rejected_*图像，
对应详细事件写入events.jsonl，便于区分视觉变化、模型歧义和处理延迟。

### 初始分类、恢复与显示

原有固定墨色阈值在AX实拍上将正确红棋变为黑棋，继而触发类别重分配。
现在默认保留高置信预测、遮挡 x 和空点；弱预测只在归一化墨迹明确时复核阵营。
类别数量冲突中的棋子按置信度从低到高，以辅助模型四个旋转视图一致性复核，
不以“合法位置”选择棋种，也不对每枚弱预测盲目套用辅助分类器。
若需改动原始至少0.90的预测，辅助证据至少需0.85；改动后立即重算计数，
冲突解除即停止复核该类别，避免连带改动其他正确棋子。
不为凑数量重分配类别；士、象、兵的可达位置仅用于独立的布局提醒。
新预览的平滑死区只作用于屏幕坐标，不改变识别或毫米测量数据。
坐标框优先沿用之前的空位，并同时避让图像中检测到的真实圆形棋子边缘，
不因一格类别不确定就隐藏它的坐标标签。
右侧灰色棋名加小圆点表示“上次确认的棋名，当前待复核”，它不是新的可信分类。
连续三次不同识别结果恢复一致后清除标记；类别变化要有两次新结果支持。
确认窗口重建期间仅在同一观察代际有新鲜候选时保留历史显示，候选不能修改显示记忆。
运动、手部遮挡、过期且无新候选、几何失效和手动重建都会清空显示记忆。
这些显示去闪动规则不会写回LiveGate.output、游戏状态或补偿数据；
“棋名字形不闪”不能当作“分类置信度一直通过”的证据。
低置信候选不因一致多次就变成高置信结果。
未通过质量检查的非遮挡盘面先尝试检测四条长棋盘边线，
有充分边线证据时使用对齐后的三个小幅水平扰动视图复核弱格。
类别数量冲突中的强预测也只有在三个边线对齐视图同类且均至少0.65时才可更改。
这项复核保留原始角点结果，不把单次霍夫边线检测强制当作新的唯一几何。
仍有疑问时可用同一个Nano在正负半档曝光下复核：
每格必须有两份足够置信的同类证据，且复核后的整盘仍须通过质量检查。
原始遮挡x不允许通过此复核被清除；这些曝光视图也不计作不同摄像头帧。
正常盘面仍只做一次推理，疑难盘面最多六次；没有切换到Tiny或固定开局答案。

采集与ONNX推理分线程，推理只取最新帧、不排队。
手部检测也与显示解耦，棋名标签缓存渲染，不让逐字绘制阻塞实时预览。
初始及恢复阶段，短暂类别抖动可由最近3次新帧中的2次一致重新确认，
原始模型的未知格和遮挡不能被投票清除；仅由增强视图分歧产生的弃权格，
可以由时间窗口内另两张新相机帧的可靠分类重新确认。
不会把未知格当作投票中的有效观测，更不会永久锁定旧图假装稳定。
投票也受时间窗口限制，较久以前的结果不能与一张新结果拼成稳态。
运动/遮挡会改变观察代际，推理中途返回的旧结果无法重新激活标注。
手部检测独立于运动，因此静止手也能触发暂停，识别能力仍以实测为准。
相机原始帧超过0.6秒不更新就暂停。直接神经分类结果可用时限为采集后2秒；
仅用于显示的上次盘面最多保留4秒，并明确显示“结果更新中”。
该显示保留不提供可信输出；手部、移动或断流会立即清除显示及待处理结果。
本轮已另外修复 main.py 的事务式走棋确认、软件棋局同步和动作后新帧复核，
并增加独立模拟验收。这个观察入口仍不提交游戏走法或触发动作。
完整启动、标定、协议与受控上机步骤见 [视觉离线验收与首次上机操作](vision-readiness.zh-CN.md)。

## 光照离线评估

tools/evaluate_vision_lighting.py使用与实时入口相同的observe_board单帧分类流程；
它不建立时序外观参考，不能用其结果直接代替连续跟踪验收。
真值manifest要求逐图10x9字符矩阵、人工标注来源、拍摄/局面分组和源文件SHA-256。
运行时显式传入 --manifest 和项目外的 --output-dir。模拟条件是半档明暗、
温和偏暖/偏冷、柔和阴影、侧光和局部提亮，不是实际室外光照的替代证明。
重复帧、增强图和用于改进的开发样本均不能当作独立盲测。
同时看整盘全对率、棋子正确率、拒绝覆盖率和错误放行数，不能只报告空格占多数的逐格准确率。
